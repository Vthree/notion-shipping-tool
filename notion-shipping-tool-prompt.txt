==================================================
一、共同執行要求
==================================================

1. 工具必須是單一 HTML 檔案，可直接雙擊並由最新版 Chrome、Edge 或 Safari 開啟。
2. 不需要安裝程式、套件、擴充功能或啟動伺服器。
3. 不使用 CDN、外部 JavaScript、外部字型、外部圖片或任何網路資源。
4. CSV、XLSX 的讀取、整理、ZIP 解壓縮、XLSX 產生、JPG 繪製、ZIP 打包及下載全部在瀏覽器本機完成。
5. 使用者資料不可上傳網路。
6. 產生的檔案必須是真正、合法的標準 XLSX，不可把 CSV、XML 或 HTML 偽裝成 XLSX。
7. Microsoft Excel 開啟時不可出現修復警告、移除記錄、格式損壞或整張表空白。
8. JavaScript 不可有語法錯誤，桌面版與手機版都要能正常使用。
9. 支援點擊選檔及拖曳上傳。
10. 選檔後立即處理並顯示預覽、統計與清楚的錯誤訊息。
11. 尚未讀入有效檔案時停用下載按鈕。
12. 介面使用繁體中文，需有明確設計感並支援響應式顯示。

工具內有三個彼此獨立的功能頁籤：

1. Notion CSV 轉 Excel 出貨撿貨表。
2. 出貨單轉成順豐下單表。
3. 清關發票對應生產器。

第二項功能不可直接拿第一項剛輸出的檔案自動串接；中間需要使用者人工整理後，再獨立匯入 XLSX。

==================================================
二、功能一：Notion CSV 轉 Excel 出貨撿貨表
==================================================

原始資料為 Notion 匯出的 UTF-8 CSV，常見來源欄位如下：

A 訂購人
B 代傳證件
C 備註
D 出貨編號
E 加固
F 加固費用(加購)
G 商品資訊
H 地址
I 快遞單號
J 打包
K 收件人
L 訂單編號
M 資料確認
N 運送方式
O 電話

程式必須優先依欄位名稱找資料，不可只依賴固定欄位位置。必要來源欄位為：

- 出貨編號
- 收件人
- 加固
- 商品資訊
- 電話
- 地址

缺少必要欄位時，必須指出缺少的欄名、停止處理並停用下載。

功能一提供兩種匯出版本，預設為「順豐到付」：

順豐到付共 10 欄：

1. 出貨編號
2. 收件人
3. 同人
4. 加固
5. 商品資訊
6. 數量
7. 撿貨員
8. 打包員
9. 電話
10. 地址

順豐寄付共 12 欄：

1. 出貨編號
2. 收件人
3. 同人
4. 加固
5. 商品資訊
6. 數量
7. 重量
8. 尺寸
9. 撿貨員
10. 打包員
11. 電話
12. 地址

切換到付／寄付時不需重新匯入 CSV，預覽和下載內容要立即跟著切換，但資料順序與綁定不可改變。

CSV 處理規則：

1. 每一筆 CSV 資料列先建立完整訂單物件，綁定出貨編號、收件人、加固、商品、電話、地址後才能排序。
2. 不可分開排序欄位，不可讓出貨編號、收件人、商品、電話、地址錯位。
3. 依出貨編號中的數字段由小到大排序，但輸出時完整保留原始出貨編號文字。
4. 沒有出貨編號的訂單放在最後，彼此維持原始順序。
5. 出貨編號相同時維持原始 CSV 順序。
6. 商品資訊中的每個換行代表一個商品列，商品原始順序不可改變。
7. 從每項商品末端辨識 x1、x2、X1、ｘ1、×1 等數量格式；數量移到「數量」欄。
8. 數量後方若有備註，備註保留於商品名稱。
9. 不可把書名中的 1-3、1-5、集數、型號等誤判為數量。
10. 找不到數量時預設為 1，並計入「未辨識數量」。
11. 電話必須以文字格式輸出，不可變科學記號、不可出現 .0、不可遺失前導 0；例如 tel:13333284018 必須完整保留。
12. 出貨編號必須以文字格式輸出，不可自行產生、改號、補號或重新編號。

合併規則：

- 同人、加固在同一訂單的多個商品列間縱向合併。
- 寄付版的重量、尺寸也在同一訂單內縱向合併。
- 合併範圍不可跨訂單。
- 出貨編號、收件人、電話、地址只在訂單第一個商品列顯示，後續列留空，但不合併。
- 撿貨員、打包員每個商品列都保留獨立空白格，不合併。
- 商品資訊與數量不合併。

Excel 樣式：

1. 標題列為深綠底、白色粗體、文字置中。
2. 凍結第一列。
3. 全表使用 Microsoft JhengHei 或相容中文字體，內容使用粗體。
4. 所有實際儲存格有黑色 thin 框線。
5. 每筆訂單 A 到最後一欄的外圍再套用黑色 thick 外框，內部仍保留 thin 框線。
6. 出貨編號欄使用淺灰底並置中。
7. 同人、加固、數量、重量、尺寸、撿貨員、打包員置中。
8. 商品資訊與地址自動換行，欄寬足以閱讀。
9. 工作表名稱為「出貨表」。
10. 橫向列印並縮放至一頁寬。
11. 不加入會與合併儲存格衝突的自動篩選。
12. 框線必須用儲存格 border，不能用 Shape、drawing 或浮動線條模擬。

商品資訊若包含精確的 `[豎排]`：

- 只有「豎排」兩字顯示紅色粗體。
- 左右方括號保持黑色粗體。
- `[橫排]`、`[繁體豎排]` 不套用。
- 同一商品出現多個完整 `[豎排]` 時全部處理。
- 必須使用合法的 XLSX rich text，Excel 開啟不可修復。

功能一預覽與統計：

- 有效訂單數。
- 商品列數。
- 商品總數量。
- 未辨識數量商品數。
- 全部商品列預覽，不限制顯示筆數。
- 預覽需模擬欄位、合併、粗細框線、灰底、紅字，並可水平及垂直捲動。

功能一下載檔名沿用上傳 CSV 原檔名，只把 `.csv` 改成 `.xlsx`，不可固定檔名或自行用日期重命名。

==================================================
三、功能二：出貨單轉成順豐下單表
==================================================

此功能匯入人工整理後的 XLSX，再產生符合順豐官方下單模板的 XLSX。

參考附件：

- `0706順豐寄付.xlsx`：人工整理後的測試輸入。
- `範例-空白表單-順風下單表-寄付.xlsx`：寄付輸出模板；檔名中的「順風」是誤字，實際名稱為順豐。
- `範例-空白表單-順風下單表-到付.xlsx`：到付輸出模板；檔名中的「順風」是誤字。

輸入 XLSX 的必要欄位：

- 出貨編號
- 收件人
- 商品資訊
- 數量
- 電話
- 地址

程式必須遍歷工作簿中的工作表，找到包含全部必要欄位的表。缺少必要欄位時顯示錯誤並停用下載。

同一出貨編號可能跨多列：

1. 有出貨編號的列建立或切換目前訂單。
2. 後續出貨編號空白的商品列仍屬於前一筆訂單。
3. 收件人、電話、地址若在後續列出現非空值，仍合併回目前訂單。
4. 最終以出貨編號建立唯一訂單映射，商品不可配到其他收件人。
5. 出貨編號內容不可修改。

付款方式提供三個單選項目：

1. 自動。
2. 到付，可人工覆寫。
3. 寄付，可人工覆寫。

自動判斷的唯一標準如下，檔名不可覆蓋此判斷：

- 工作表同時有「撿貨員」及「打包員」欄位：判斷為寄付。
- 缺少其中任一欄位：判斷為到付。

介面中必須清楚顯示目前判斷結果，並說明上述規則。

==================================================
四、順豐下單表模板與資料列規則
==================================================

1. 完整保留模板第 1、2 列，不可刪除或修改。
2. 從第 3 列開始填入實際資料。
3. 以模板第 3 列為資料列樣板，所有輸出資料列逐欄保留其樣式、固定值及資料型態。
4. 保留模板的欄寬、列高、合併儲存格、註解、資料驗證、條件格式、工作表設定、頁面設定、列印設定及其他 XLSX 元件。
5. 只輸出實際資料列，不要求保留模板後方未使用的空白預填列。
6. 工作表範圍更新為 A1:BR最後資料列。
7. 寄付與到付目前使用相同且已驗證可正常顯示的寄付模板作為基底，再逐列明確改寫 AA 與 BK；這可避免部分 Excel 版本開啟到付模板時變成整張空白。
8. 產生的 XLSX 除工作表實際資料 XML 外，其餘模板套件內容應保持不變。

輸出欄位映射：

- A：寄件方姓名，文字。
- B：寄件方手機號，文字。
- D：寄件方詳細地址，文字。
- S：客戶訂單號，填入原始出貨編號，文字且不可修改。
- T：收件方姓名，文字。
- U：收件方手機號，文字，不可有 .0、科學記號或遺失前導 0。
- V：收件方詳細地址，文字。
- W：商品名稱，文字。
- X：商品數量，數值。
- Z：商品單價，數值。
- AA：付款方式，到付填「到付」，寄付填「寄付」。
- BK：月結卡號；寄付固定填數值 `8860748596`，到付必須是完全空白的儲存格。

其餘欄位保留模板第 3 列的固定預設值與樣式。所有標有 `*` 的順豐必填欄位，在每個實際資料列中都不可空白。

順豐下單表預覽至少顯示：

- 出貨編號
- 寄件方姓名
- 寄件方手機號
- 寄件方詳細地址
- 收件方姓名
- 收件方手機號
- 收件方詳細地址
- 商品名稱
- 商品數量
- 商品單價
- 付款方式
- 月結卡號

預覽顯示全部輸出商品列，不限制顯示筆數。

五、功能二商品保留與單價規則
==================================================

1. 每一個非空商品列都必須輸出，書籍、週邊、贈品、檔案袋、大全套、番外冊及其他類型都不可排除。
2. W 欄商品名稱必須與人工整理後的來源 XLSX 完全一致，不可刪除、截斷、簡化、改名或重組。
3. 必須完整保留商品名稱開頭的所有方括號標籤。
4. 必須完整保留 `(書籍)`、`(週邊)` 後方的備註文字。
5. 相同商品重複出現時仍逐列保留，不可合併同名商品或加總成單一列。
6. 商品列順序必須與來源 XLSX 一致。
7. 範例：`[留守番][預售][印簽版]花近江國1-3(書籍)` 輸出後必須保持完全相同，不可變成 `花近江國1-3(書籍)`。
8. 範例：`吞海-加購大全套(週邊)` 必須正常輸出，不可因為不是書籍而消失。

商品單價：

1. 一般每冊 200。
2. 3 冊組合固定 500。
3. 依 `[第1-3集]`、`[上+中+下]` 或書名末端 `1-3(書籍)` 等格式計算冊數。
4. 特例：`全世界都在等我們分手1-3(書籍)` 為 400。
5. 特例：`[第3-6集]PASSION(書籍)` 為 500。

七、功能二輸出檔名
==================================================

格式：

`YYYYMMDD-快遞下單-大陸-XXX.xlsx`

規則：

1. 優先從第一筆出貨編號取得 8 位日期。
2. 若沒有，再從原檔名取得 8 位日期。
3. 原檔名只有 MMDD 時，前面加目前年份。
4. 都沒有日期時才使用當天日期。
5. `XXX` 取原檔名最後一個連字號後的文字。
6. 原檔名沒有連字號時使用 `XXX`。
7. 移除「完成版、重做版、修正版、最終版、final」等尾碼。
8. 不加入完成版、重做版或修正版等尾碼。
9. 清除 Windows 檔名不允許的字元。
10. 瀏覽器因重複下載自動加上的 `(1)`、`(2)` 不屬於工具產生的檔名規則。

==================================================
八、XLSX 及 ZIP 相容性
==================================================

1. 必須能讀取標準 XLSX ZIP，包括 method 0 與 deflate method 8。
2. 需要處理 shared strings、inline strings、一般數值及工作表列／欄座標。
3. 重新建立 ZIP 時 CRC32、大小、偏移、中央目錄與 UTF-8 檔名都必須正確。
4. XML 特殊字元必須跳脫，移除 XML 不允許的控制字元。
5. 不可產生不存在的 style ID、font ID、fill ID、border ID 或 number format ID。
6. 不可破壞模板的 comments、VML drawing、relationships、shared strings、styles、theme 或 docProps。
7. 手機與訂單號使用文字儲存；數量、單價、寄付月結卡號使用數值儲存。
8. 到付 BK 儲存格必須真正空白，不可留下空字串、0 或寄付模板的卡號。

==================================================
十、功能三：清關發票對應生產器
==================================================

此功能取代原本只適用 macOS 的 `run.command`、Python、pandas 與固定 Chrome 路徑流程。所有處理必須直接在單一 HTML 的瀏覽器內完成，在 Windows 與 macOS 都不需安裝其他程式。

使用者需同時匯入兩份彼此獨立的 XLSX：

1. 順豐下單表，常用檔名 `orders.xlsx`。
2. 順豐運單對照表，常用檔名 `sf.xlsx`。

介面需提供兩個可點擊或拖曳的選檔區，只有兩份檔案都成功讀取且發票設定完整時才啟用下載。

`orders.xlsx` 必要欄位如下；欄名前方的 `*` 可存在，判斷時需正規化：

- 客戶訂單號
- 收件方姓名
- 收件方手機號
- 收件方詳細地址
- 商品名稱
- 商品數量
- 商品單價

`orders.xlsx` 處理規則：

1. 順豐官方模板第 2 列可能是「必填、max」欄位說明，不可誤當成真實訂單。
2. 依客戶訂單號分組，每個客戶訂單號產生一張發票。
3. 訂單按客戶訂單號排序，商品維持來源列順序。
4. 商品數量與單價轉為整數；無法辨識時依原 Python 邏輯視為 0。
5. 每列金額為商品數量乘以商品單價；發票總計為同訂單全部商品金額加總。
6. 品名、收件資料若包含「公司統編」或「未完成交易」則清為空白，其餘文字去除頭尾空白並最多保留 100 字。
7. 手機號碼不可出現 `.0` 或科學記號；可辨識時保留前導 0。

`sf.xlsx` 必要欄位：

- 順豐運單號(母單號和子單號)
- 客戶訂單號

以客戶訂單號建立對照，將順豐運單號配到相同訂單；不可依資料列位置配對。找不到運單時仍需產生發票，檔名使用 `NO_SF_客戶訂單號.jpg`，並在預覽與統計中警告。

發票設定欄位與預設值：

- 營業人名稱：`一豆文化有限公司`
- 營業人統編：`90377625`
- 發票字首：`ZL`
- 發票日期：預設本機當天，格式 `YYYY-MM-DD`

每次成功讀取兩份檔案時產生一個隨機 8 位數起號；同批訂單依序加 1，並在前方加上使用者設定的發票字首。同一次預覽與下載必須使用相同號碼，不可在按下載時重新亂數造成預覽不一致。

每張電子發票明細至少包含：

- 發票號碼
- 發票日期
- 發票狀態固定為「已開立」
- 發票備註：收件方手機號、換行、收件方地址
- 營業人統編
- 營業人名稱
- 買受人統編固定為 `-`
- 買受人名稱
- 課稅別固定為「免稅」
- 總計
- 全部商品的品名、數量、單價及金額

JPG 與下載規則：

1. 使用瀏覽器 Canvas 直接繪製真正的 JPEG，不可把 HTML 或 SVG 偽裝成 JPG。
2. 版面以原工具 1200 × 1600 的電子發票明細為基礎；商品過多時高度需自動增加，避免裁掉商品。
3. 使用 Microsoft JhengHei 或系統相容中文字體，灰底表頭、白底內容與淺灰框線。
4. 每張 JPG 以對應的順豐運單號命名；Windows 不允許的檔名字元必須清除。
5. 運單號重複時不得覆蓋，後續檔名加 `-2`、`-3`。
6. 全部 JPG 放在 ZIP 內的 `output_jpg/` 資料夾。
7. ZIP 檔名為 `YYYYMMDD-清關發票-JPG.zip`，日期取發票日期。
8. ZIP MIME type 使用 `application/zip`，CRC32、大小、UTF-8 檔名與中央目錄必須正確。

預覽顯示全部訂單，不限制筆數，至少包含客戶訂單號、順豐運單號／JPG 檔名、發票號碼、買受人、商品列數、總計與檢查結果。統計需顯示訂單數、已對應運單數、總額超過 3,000 元筆數及未對應運單筆數。總額超過 3,000 元只需警告，不可寫入或遮蓋發票圖片內容。

功能三驗收至少包含：

1. 使用附件 `orders.xlsx` 與 `sf.xlsx` 可讀取 98 筆真實訂單，排除模板說明列。
2. 共保留 224 個商品列。
3. 98 筆訂單全部依客戶訂單號對應到順豐運單。
4. 第一筆訂單為 `20260706-001`，最後一筆為 `20260706-098`。
5. 預覽完整顯示 98 筆。
6. 產生的 ZIP 可正常解壓，JPG 位於 `output_jpg/` 且檔名使用順豐運單號。
7. 功能一與功能二原有測試仍需全部通過，不可因新增功能而回歸。
